The possible values each category can take in Table 3 are arbitrarily defined within this hypothetical scenario 
but should be adapted to the possible range of operational conditions in the desired deployment environment 
when this framework is employed in a real-world scenario. If we were to examine the robustness of the CV 
system under test individually under each parameter, and only produce results for each row, we may be 
unable to pick up possible blind spots on images containing more than one parameter of interest, e.g. images 
containing multiple small drones with high noise and dark ambient light. However, if we were to use every 
possible combination of parameters in testing, we would end up with a very large set of test cases which 
would be unlikely to be fulfilled by our collected dataset, and computationally prohibitive to generate 
otherwise. Hence, to simplify the resulting conversion of the above eleven test levels for the 5 parameters 
into test cases, we use pairwise subsets of the parameters, e.g. image noise vs. ambient light, to derive user 
friendly test tables. All possible parameter combinations would lead here to prod_{k = 1}^{d} n_d 
combinations, here 3* 2^4 = 48.
